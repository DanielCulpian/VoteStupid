# Local Docker operations

## Services and storage

Nginx serves the compiled Vue app and proxies HTTP/WebSocket requests to FastAPI. PostgreSQL 17 and the API are reachable only on the internal Docker network. The only published port is `127.0.0.1:8080`. FastAPI runs without root, with a read-only filesystem and one worker.

The external volume defaults to `votestupid_postgres_data`. Compose refuses to start if it is missing. This prevents a renamed project from silently creating a different database.

Before changing storage, inspect the current mount:

```sh
docker inspect --format '{{range .Mounts}}{{.Name}} {{.Destination}}{{end}}' votestupid-db
docker volume inspect votestupid_postgres_data
```

For a genuinely new installation, create a new empty volume explicitly. Set `POSTGRES_VOLUME_NAME` to the correct existing volume when upgrading. Never delete volumes, remove their files, or run `docker compose down -v`.

Data stays on the host running Docker; it is not part of Git or the application images. There is no startup seed or bundled poll database. Do not copy a private volume or backup when distributing a clean installation.

## Configuration

Copy `.env.example` only when no private `.env` exists.

| Variable | Purpose |
| --- | --- |
| `POSTGRES_PASSWORD` | Existing database password, or a new strong password before initializing a new volume |
| `ADMIN_PASSWORD_HASH` | scrypt hash generated by the configurator; quote it in single quotes |
| `ADMIN_COOKIE_SECURE` | `false` for local HTTP; public tunnel mode forces `true` |
| `POSTGRES_VOLUME_NAME` | Explicit persistent volume name |
| `HTTP_PORT` | Loopback HTTP port, default 8080 |
| `DOCKER_PUBLIC_ORIGIN` | Exact local origin, default http://localhost:8080 |
| `DOCKER_INTERNAL_SUBNET` | Internal application network, default 172.30.78.0/24 |
| `NGINX_INTERNAL_IP` | Nginx address in that subnet, default 172.30.78.10 |
| `CLOUDFLARE_TUNNEL_TOKEN` | Optional named-tunnel secret; not used for Quick Tunnels |

Changing `POSTGRES_PASSWORD` does not rotate a password inside an existing volume. Preserve its actual credentials. Do not print `docker compose config` into shared logs because resolved configuration contains secrets; use `docker compose config --quiet`.

## Start, stop, and inspect

From the repository root on Windows:

```powershell
.\scripts\docker.ps1 start
.\scripts\docker.ps1 status
.\scripts\docker.ps1 logs
.\scripts\docker.ps1 stop
```

The scripts locate Docker on PATH or in its per-user Windows installation. They do not overwrite the user's private local launcher scripts. Start/stop also stop any tunnel connector before switching to local mode.

Equivalent Linux commands:

```sh
docker compose -f compose.yaml -f compose.tunnel.yaml stop cloudflared
docker compose up -d --build --wait --wait-timeout 180
docker compose ps -a
docker compose logs --tail 100 -f
docker compose stop
```

The tunnel stop command is harmless if no connector exists. Ctrl+C exits log following only.

## Migrations and health

PostgreSQL must pass its readiness check before backend startup. The backend then runs `alembic upgrade head` before replacing itself with Uvicorn. Migration failure prevents API startup; it never resets the schema. One API worker is required by the in-memory limiter and WebSocket registry.

Health checks cover PostgreSQL, an actual catalog query through the API, and Nginx. Inspect failures using `docker compose logs --tail 100 backend`. Back up before updating the application and inspect migration changes before applying them to valuable data.

## Host development

The optional development override exposes PostgreSQL only on loopback:

```powershell
docker compose -f compose.yaml -f compose.dev.yaml up -d --wait db
docker exec votestupid-db createdb -U votestupid votestupid_test
```

Create the test database only if it does not already exist. Host Python uses a private `DATABASE_URL` with `127.0.0.1:5432`, user `votestupid`, and the existing password. URL-encode special password characters.

```powershell
$env:PYTHONPATH = 'backend'
python -m pytest -v
python -m uvicorn app.main:app --app-dir backend --reload
```

On Linux use `PYTHONPATH=backend python -m pytest -v`. Frontend development uses Node 24, `npm ci`, and `npm run dev` from `frontend/`. Configure `VITE_API_URL=http://localhost:8000` and `CORS_ALLOWED_ORIGINS=http://localhost:5173`; use the same hostname for both services.

Normal Compose startup removes the optional database port. Do not enable the development override when publishing the application.

## Network conflicts

Change `HTTP_PORT` and `DOCKER_PUBLIC_ORIGIN` together. If the internal subnet conflicts with another Docker/VPN network, update `DOCKER_INTERNAL_SUBNET` and `NGINX_INTERNAL_IP` together. The tunnel has a separate fixed network documented in the tunnel guide.

Reference: [Compose startup order](https://docs.docker.com/compose/how-tos/startup-order/).
